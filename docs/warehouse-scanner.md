# מסופון מחסן (`/scanner`)

אפליקציית Web/PWA למסופון Android עם סורק מובנה, למשל Newland MT93. העובד מתחבר פעם אחת ועובד רק בסריקות, בלי מחשב.

## הגדרת המכשיר
1. מגדירים את הסורק במצב **Keyboard Wedge** (בלשון היצרן: Keyboard emulation / Output to keyboard), עם **סיומת Enter**.
2. פותחים בדפדפן Chrome את `https://<השרת>/scanner`, מתחברים, ובוחרים ״הוספה למסך הבית״. האפליקציה תיפתח במסך מלא.
3. המקלדת הרכה לא נפתחת (`inputMode=none`). להקלדה ידנית לוחצים על כפתור המקלדת.

## מצבי עבודה
| מצב | רצף סריקות |
|---|---|
| אחסון | מדף ← ספר ← ספר… ← מדף אחר ← ספר… (המדף הפעיל מתחלף אוטומטית) |
| העברה | מיקום יעד ← הספרים המועברים |
| איתור | ספר ← שם, תמונה, מספר, מיקום, שיוך, מצב מסחרי ופעולות מותרות |
| ליקוט | רשימת המשימות ממוינת לפי סדר המדפים. סריקת הספר מאמתת שזה הפריט הנכון ← ״לוקט״ |
| ספירת מלאי | בוחרים אזור ← מיקום ← כל הספרים שבו. **שום מיקום אינו משתנה** עד שמנהל מאשר את הפערים בדו״ח |

ברקודי פקודה (`/labels/commands`): `CMD-STORE`, `CMD-TRANSFER`, `CMD-FIND`, `CMD-PICK`, `CMD-COUNT`. הם מחליפים את מצב המסופון בלבד. כל פעולה נבדקת בשרת מול הרשאות המשתמש המחובר.

אחרי כל סריקה מוצגים: הודעה גדולה (ירוקה, כתומה או אדומה), שם הספר, מספר המלאי והמיקום. בנוסף נשמע צליל ייחודי לכל תוצאה, ובשגיאה המכשיר גם רוטט.

## אמינות וניתוק
- **כל סריקה נכתבת ל-IndexedDB לפני שהיא נשלחת לשרת**, עם `opId` ייחודי שנוצר ברגע הסריקה.
- כל סריקה מקבלת סטטוס: **נשמר בשרת** (אחרי תשובה מהשרת), **ממתין לסנכרון**, **נכשל** או **דורש טיפול**. סריקה ממתינה לעולם אינה מוצגת כאילו אושרה.
- במצב לא מקוון, סריקת מדף מוכר עובדת מתוך מטמון המיקומים שבמכשיר. הסנכרון רץ לפי סדר הסריקות כשהחיבור חוזר, וגם כל 15 שניות.
- שליחה חוזרת של אותו `opId` מחזירה את התוצאה המקורית ואינה מבצעת את הפעולה שוב. סריקה כפולה של ספר שכבר נמצא במדף מסומנת ״ללא שינוי״.
- סריקה שמסונכרנת באיחור, כשהספר הוזז בינתיים על ידי מישהו אחר, **אינה מבוצעת**. היא נשמרת כ-CONFLICT ומחכה להחלטת מנהל ב-`/scans`.
- שעון המכשיר משמש להשוואת זמני הסריקה. מומלץ להשאיר במכשיר עדכון זמן אוטומטי.

## API ומתאם עתידי
- `POST /api/scan` מקבל פעולה אחת. `POST /api/scan/batch` מקבל עד 200 פעולות (פריקת התור הלא-מקוון). החוזה: `scanOpSchema` ב-`packages/shared`.
- מתאם API של המכשיר (בלי Keyboard Wedge): עטיפת WebView נייטיב יכולה לקרוא ל-`window.avotScanner.push(code)` או לשלוח `CustomEvent("avot-scan", { detail: { code } })`. **אפליקציה נייטיב לא נבנתה בשלב זה.**
- Service Worker (`/scanner-sw.js`, פעיל ב-build של Production בלבד) שומר את מעטפת הדף, כדי שהמסופון ייפתח גם בלי רשת. הוא לעולם אינו שומר תשובות API.


## מסופון בטלפון (מצלמה) — ללא חומרה ייעודית

כל עובד עם הרשאה נכנס ל-`/scanner` מכל טלפון (מומלץ להוסיף למסך הבית; PWA, לא חובה). דרוש **HTTPS** — דפדפנים חוסמים מצלמה בלעדיו.

**מסך ראשון** — חמש פעולות גדולות, בעברית פשוטה (בלי STORE / PICK וכו׳):
הכנסת ספר למחסן · הוצאת ספר מהמחסן (זמנית · ליקוט להזמנה · סופית) · העברת ספר בין מדפים · איתור ספר · ספירת מלאי.

**בכל פעולה** מוצגת הוראה ברורה לשלב הנוכחי (״סרוק מדף״ ← ״סרוק ספר״), והמצלמה האחורית נשארת פתוחה לאורך הרצף:

| פעולה | רצף |
|---|---|
| הכנסת ספר | סרוק מדף ← סרוק ספרים ברצף (כל ספר משויך למדף) ← אפשר להחליף מדף בלי לצאת |
| העברה | סרוק מדף **יעד** ← סרוק את הספרים (מדף המקור ידוע למערכת ואין צורך לסרוק אותו) |
| הוצאה זמנית | סרוק ספר ← הוא יורד מהמדף ומסומן ״ממתין לאחסון״ עד שיוחזר |
| ליקוט להזמנה | משימות ממוינות לפי סדר מדפים; סריקת הספר מאמתת ומסמנת ״לוקט״ |
| הוצאה סופית | סרוק ספר שנמכר ← נרשם ליקוט, אריזה ומשלוח; דורש משימת משלוח |
| איתור | סרוק ספר ← שם, תמונה ומיקום מדויק |
| ספירה | בחר ספירה ← מדף ← ספרים; פערים מוצגים, **מיקומים לא משתנים** בלי אישור מנהל |

**טכני:** זיהוי Code 128 ו-QR בצד המכשיר (`BarcodeDetector` כשקיים, אחרת ZXing מצורף); פנס כשהמכשיר מאפשר; הקלדה ידנית; צליל ורטט; מניעת קריאה כפולה (אותו ברקוד לא נקלט שוב כל עוד נשאר בפריים, ועוד 2.5 שניות); אין שליחת וידאו או תמונות לשרת. ללא חיבור: כל סריקה נשמרת במכשיר וממתינה לסנכרון — **לא מוצג ״נשמר״ לפני אישור השרת**. תווית עמודה (`COL-…`) נדחית בהסבר: ספר מוצמד רק למדף מדויק.

סורק פיזי במצב Keyboard Wedge ממשיך לעבוד כרגיל (שדה הקלט נשאר ממוקד).
