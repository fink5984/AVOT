# אבטחה, גיבויים ושחזור

## אימות והרשאות
- סיסמאות: scrypt (N=2^15, r=8, p=1), מינימום 10 תווים. אין שמירת סיסמאות גלויות.
- Sessions: אסימון אקראי 256 ביט בעוגיית HttpOnly + SameSite=Lax (+Secure ב-HTTPS); נשמר כ-SHA-256 בלבד; תוקף מתגלגל 14 יום; השבתת משתמש מנתקת את כל ה-sessions שלו.
- CSRF: כל בקשה משנה מצב עם עוגיית session חייבת Origin תואם לאתר.
- הרשאות נבדקות בשרת בכל route (`src/server/auth/permissions.ts`) — הסתרת כפתורים היא נוחות בלבד. כל שאילתה מסוננת לפי `organizationId`.
- Rate limiting: כניסה (8 כשלונות לאימייל / 30 ל-IP ב-15 דק׳), צימוד, הזמנות, איפוס. בזיכרון — מופע יחיד.
- הזמנות ואיפוס סיסמה: קישור חד-פעמי (7 ימים / שעתיים), מועבר ידנית על ידי מנהל (אין שליחת אימייל במערכת).

## קבצים
- מפתחות אחסון אטומים (UUID), ללא מידע אישי. הדלי פרטי.
- גישה לתמונה: רק דרך route מאומת שבודק ארגון והרשאה, ואז הפניה לקישור חתום ל-5 דקות (S3/R2) או HMAC חתום (אחסון מקומי). ניחוש URL אינו נותן גישה (נבדק ב-E2E).
- קובצי ZIP: עבודת רקע, קישור חתום ל-10 דקות, הקובץ נמחק אחרי 48 שעות.
- XSS: React מקודד את כל הפלט; אין `dangerouslySetInnerHTML` מלבד SVG של QR שנוצר בשרת. כותרות: `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy` (מצלמה רק לאתר עצמו).
- Validation: Zod בכל קלט; גודל הקובץ שנשלח נאכף מול הגודל שהוצהר תוך כדי הזרמה.

## Capture Agent
- מאזין ל-127.0.0.1 בלבד; Host allow-list; CORS לאתר המצומד בלבד; control token חתום (HMAC) לכל משתמש+Origin, בתוקף 8 שעות; Lease יחיד.
- אסימון העמדה וסוד ה-HMAC מוצפנים ב-DPAPI (משתמש Windows); בשרת — האסימון נשמר כ-hash, הסוד מוצפן AES-256-GCM במפתח הנגזר מ-`APP_SECRET`.
- ביטול עמדה במסך העמדות חוסם אותה מיד.

## Audit log
כל פעולה חשובה נרשמת (`AuditLog`): כניסה, צילום, מחיקה/שחזור/מחיקה לצמיתות, העברות, שינוי סטטוס, ייצוא, משתמשים, עמדות. מוצג במקום אחד: הגדרות ← ״יומן פעילות״ (מנהלים). היסטוריה של ספר מסוים: תפריט ״⋯״ במסך הספר ← ״היסטוריית פעולות״.

## גיבוי ושחזור — מדיניות מומלצת
| מה | איך | תדירות | שמירה |
|---|---|---|---|
| PostgreSQL | Railway Postgres backups (מנוהל) + `pg_dump` לאחסון חיצוני | יומי | 30 יום |
| מקורות בדלי | R2/S3 Object Versioning או העתקה לדלי שני באזור/ספק אחר (rclone sync) | יומי | ללא מחיקה (מקורות של פריטים יקרי ערך) |
| עמדות צילום | המקורות נשארים בדיסק העמדה כברירת מחדל (`LocalRetentionDays=0`) — עותק שלישי | — | עד ניקוי ידני |

`pg_dump` ידני:
```bash
pg_dump "$DATABASE_URL" --format=custom --file=avot-$(date +%F).dump
```
שחזור לבדיקה (מומלץ אחת לרבעון, למסד ריק בסביבת staging):
```bash
pg_restore --clean --no-owner --dbname "$STAGING_DATABASE_URL" avot-YYYY-MM-DD.dump
```
לאחר שחזור: לכניסה למערכת, פתיחת קטלוג, צפייה בתמונה (מוודא שהמפתחות במסד תואמים לדלי) והורדת ZIP קטן.

## בדיקות שלמות תקופתיות
- כל קובץ נשמר עם SHA-256 שחושב בעת ההעלאה. ״דוחות ← תקלות סנכרון״ מציג קבצים שנרשמו ולא אומתו מעל 30 דקות ועמדות עם שגיאות/דיסק נמוך.
- סריקת שלמות מלאה של הדלי מול המסד (הורדה וחישוב מחדש) — לא מומשה כעבודה אוטומטית בשלב זה; מומלץ להוסיף כעבודת רקע חודשית.
