# הדפסת תוויות — מדפסת קבועה אחת לכל המערכת

עובד, מכל מחשב או טלפון, לוחץ על סמל המדפסת — והתווית יוצאת במדפסת הקבועה. בלי חלון הדפסה של הדפדפן ובלי PDF (שניהם נשארו כאפשרות מתקדמת: `/labels/books?ids=…`).

## ארכיטקטורה

```
דפדפן / טלפון ──POST /api/print/jobs──▶ PrintJob (PENDING) בתור עמיד ב-PostgreSQL
                                              ▲
 סוכן הדפסה (Node, ליד המדפסת) ──חיבור יוצא בלבד──┘  claim → השרת מרנדר ZPL → סוכן שולח למדפסת → דיווח
```

- השרת **לא** פונה לכתובת ה-IP המקומית של המדפסת, והסוכן לא פותח פורטים נכנסים.
- הסוכן הוא `Device` מצומד מסוג `PRINT` (אותו מנגנון צימוד כמו עמדת צילום, אסימון Bearer משלו). עמדת צילום לא יכולה לתפוס משימות הדפסה, ולהפך.
- **מצבי משימה:** ממתין → (נתפס) → **נשלח למדפסת** → **הושלם** / נכשל / בוטל. ״הושלם״ מוצג רק כשהמדפסת **אישרה** (אחרי `~HS`: אין פורמטים בחיץ ואין מדבקה ממתינה). מדפסת שלא עונה ל-`~HS` נשארת ב״נשלח למדפסת״ והממשק אומר זאת במפורש.
- **מניעת כפילות:** (1) `idemKey` לכל לחיצה — לחיצה כפולה / בקשה חוזרת לא יוצרות משימה נוספת; (2) יומן מקומי בסוכן (`journal.json`) — משימה ש״נשלחה״ לא תישלח שוב אחרי הפעלה מחדש, ומשימה שנקטעה **באמצע** שליחה מסומנת כנכשלה (לא מנחשים); (3) נעילת `claim` עם `FOR UPDATE SKIP LOCKED`. משימה שנתפסה ולא דווחה תוך 2 דקות חוזרת לתור, עד 3 ניסיונות.
- אצוות גדולות מתפצלות למשימות של עד 40 תוויות, לפי הסדר.

## התקנת סוכן הדפסה

חיבור פיזי: **Ethernet (מומלץ)** — סוכן ב-Windows או Raspberry Pi; או **USB** — מחשב Windows קבוע.

1. באתר: הגדרות ← **מדפסת תוויות** ← ״צימוד סוכן חדש״ (קוד בן 8 ספרות, תקף 15 דקות).
2. במחשב הסוכן (Node.js ≥ 20.18), מתיקיית `apps/print-agent`:
   - Windows (שירות עולה עם המחשב): `deploy\install-windows.ps1 -Server https://<האתר> -Code <קוד>`
   - ידנית: `node src/cli.mjs pair --server https://<האתר> --code <קוד>` ואז `node src/cli.mjs run`
   - Raspberry Pi: `deploy/avot-print-agent.service` (systemd).
3. באתר: ״הוספת מדפסת״ — דגם, חיבור (רשת: כתובת IP וקבועה; USB: שם המדפסת ב-Windows), גודל מדבקה, רזולוציה, ״הגדרה כראשית״, ״הדפסת ניסיון״.

אסימון הסוכן נשמר ב-`%ProgramData%\AvotPrintAgent\config.json` (Linux: `~/.avot-print-agent`). ביטול הסוכן בעמוד העמדות מנתק אותו מיד.

## תוכן התוויות

| תווית | תוכן |
|---|---|
| ספר | שם הספר בעברית (RTL, מתכווץ או נחתך בסוף כדי להיכנס), ברקוד **Code 128** שמקודד בדיוק את `InventoryItem.barcode` (לא מיוצר מחדש בכל הדפסה), מספר מלאי קריא |
| מדף | ״מדף N״ גדול, מסלול (מחסן › עמודה), ברקוד `LOC-…` וקוד קריא |
| עמודה | שם העמודה והמחסן וברקוד `COL-…` (מזהה עמודה בלבד: מסופון **לא** יקבל אותו כמיקום — ספר מוצמד רק למדף מדויק) |

הברקוד הוא `^BC` ילידי של המדפסת (סריק, חד); רוחב המודול מותאם כדי שגם ברקוד חיצוני ארוך ייכנס. **העברית מצוירת בשרת** (גופן Heebo, רישיון OFL, ב-`apps/web/assets/fonts`) ונשלחת כגרפיקה (`^GFA`), ולכן אינה תלויה בגופנים שבמדפסת. גדלי מדבקה: ‎50×25 · 57×32 · 70×40 · 100×50 מ״מ, 203 או 300 dpi.

## מה ידוע ומה לא נבדק
- מדפסות Zebra ZPL II (ו-TSC / Honeywell במצב ZPL) צפויות לעבוד; **שפה אחרת (TSPL/EPL) לא ממומשת** — העמודה `Printer.language` שמורה להרחבה.
- ההדפסה לא נבדקה על מדפסת אמיתית (ראו [workflow-upgrade.md](workflow-upgrade.md)). בתוך מחשב Windows עם מדפסת USB משמש מסלול RAW דרך ה-spooler (`winspool`).
- הדגם הסופי עדיין לא נבחר: אשרו מול היצרן ש-`~HS` נתמך ושקיבלתם 203/300 dpi לפי ההגדרה.
